# Oath Wallet 5.0.3 (109)

Stable GitHub source release, identified by [`v5.0.3-build109`](https://github.com/OathWallet/oath-wallet/releases/tag/v5.0.3-build109). This publication does not upload to Apple or submit for review.

## Changes

- New wallet sidebar with wallet switching, organization, preferences and clear navigation.
- Asset lists update stable rows rather than rebuilding every row when one balance changes. Filtering and exact native-unit values are preserved.
- Recent activity is prepared and observed alongside the home screen. Wallet activation completes without waiting for ancillary background work.
- Wallet customization applies its committed name and color immediately, including the selected default name when the field is empty.
- Send preparation reuses work for an unchanged balance, while preserving recipient, chain, amount and signing authorization checks. Error recovery guidance is translated into all 57 supported app languages.
- Bitcoin receipts can display bounded replacement and child-pays-for-parent fee relationships. Missing optional provider data does not change transaction signing.
- More resilient indexed balance reads, bounded provider retries, improved Fantom and Gnosis price resolution, and consistent handling of retired native-price sources.
- Improved token artwork resolution, pinned IPFS gateway recovery and rectangular artwork presentation, with existing SVG and response-size validation retained.
- Updated home, settings, language and artwork presentation. Existing wallet, backup and migration identities remain compatible.

Cronos remains disabled in the app. Package test-network fixtures do not enable test networks in the production wallet.

## Verify the source

Use the build-specific tag. The older `v5.0.3` preview and `v5.0.3-build110` tags retain their original source identities; [build 110's record](5.0.3-build110.md) is preserved. Build 109 is an explicitly selected release identifier, not an assertion of numeric ordering over earlier tags.

```sh
git clone https://github.com/OathWallet/oath-wallet.git
cd oath-wallet
git checkout --detach v5.0.3-build109
git rev-parse HEAD
python3 Distribution/verify_release.py --root . \
  --tag v5.0.3-build109 --version 5.0.3 --build 109 \
  --output /tmp/oath-5.0.3-build109-source.json
```

Compare the full commit with the release attachment `source.json`. The verifier rejects an inconsistent tag, modified tracked source, or mismatched version/build settings. Both Xcode configurations and `project.yml` identify **5.0.3 / 109**.

## Reproduce validation

Requires macOS, Xcode 27, Swift 6, Python 3 and Gitleaks. The published validation used Xcode 27.2 (27B52), Swift 6.4.2. No provider credentials are required for compilation or the offline host checks below.

```sh
sh Tools/PreparePublicBuild.sh
python3 Tools/ValidatePublicRelease.py --scan
python3 Tools/CheckDiagnosticsCoverage.py
python3 Tools/CheckLocalizationCatalog.py
python3 Tools/CheckClipboard.py
python3 -m unittest discover -s Distribution/tests -v
python3 Tools/CheckWalletSidebar.py
python3 Tools/CheckHomePortfolio.py
python3 Tools/CheckMultiWallet.py --lifecycle
python3 Tools/CheckSendBalancePreparation.py
python3 Tools/CheckScanner.py --connections
for package in OathAnkr OathDatabase OathMarketData OathBitcoin OathTokenImages; do
  swift test --package-path Packages/$package --build-system native --jobs 4 \
    --parallel --num-workers 4 --xunit-output /tmp/$package-results.xml || exit 1
done
swift test --package-path Packages/OathSidebar --build-system native --jobs 4
swift test --package-path Packages/OathDiagnostics --build-system native --jobs 4
OATH_TRACE_OUTBOX_TEST=1 swift test --package-path Packages/OathDiagnostics \
  --build-system native --jobs 4 --filter DiagnosticTraceTests
OATH_PROPAGATION_CAPTURE=1 swift test --package-path Packages/OathDiagnostics \
  --build-system native --jobs 4 --filter ReportedDiagnosticFailureTests
for configuration in Debug Release; do
  xcodebuild build -project OathAtmosphere.xcodeproj -scheme OathAtmosphere \
    -configuration "$configuration" -destination 'generic/platform=iOS' \
    -derivedDataPath /tmp/oath109-build CODE_SIGNING_ALLOWED=NO \
    > "/tmp/oath109-$configuration.log" 2>&1 || exit 1
done
python3 Tools/CheckDiagnosticsBoundary.py /tmp/oath109-build/Build/Products/Debug-iphoneos
```

The package command isolates test cases in separate processes; this avoids sharing the process-wide diagnostics recorder between unrelated suites. Opt-in live/runtime checks remain skipped and are not counted as passes. The lifecycle harness uses production session/storage code with documented synthetic derivation and no-network adapters; it is not an iOS runtime test.

See the release attachment `verification-5.0.3-build109.json` for actual results, command exit status, fixture failures found during preparation and their subsequent retests. Source identity is recorded separately in `source.json` to avoid a self-referential commit hash.

## GitHub build and later Apple delivery

In **Actions → Release app and website → Run workflow**, select `main`, version `5.0.3`, build `109`, source tag `v5.0.3-build109`, and **Verify only enabled** to validate and compile without deployment.

The maintainer can later disable **Verify only** to sign and upload through the existing workflow. That mode also deploys the website and waits for Apple processing; it does not submit for review. Confirm that Apple will accept this version/build before running it, and do not repeat an already accepted upload.

After a successful upload, inspect the `app-store-release-receipt` artifact. Its receipt must identify this exact tag, commit, version/build and Apple's build identifier. Verify its GitHub attestation:

```sh
gh attestation verify receipt.json --repo OathWallet/oath-wallet
```

A source release or unsigned build is not an Apple delivery receipt. Apple can transform the distributed binary; this is build provenance, not proof of byte-for-byte equivalence with an App Store download.
