# Oath Wallet 5.0.3 (110)

Regular GitHub source release. The immutable release tag is
[`v5.0.3-build110`](https://github.com/OathWallet/oath-wallet/releases/tag/v5.0.3-build110).
Apple upload, processing, review and public availability are separate steps. This
release does not claim that build 110 has been delivered to or approved by Apple.

## Changes included

- Faster send preparation across supported networks, with shared, cancellable
  balance work scoped to the selected wallet, account, chain and asset. Fresh
  results can be reused at the same validated block; final recipient, signing and
  authorization checks remain in place.
- Clearer Send Review totals for native amounts, transfer charges, network fees,
  XRP charges, and storage or rent requirements. Atomic-unit signing amounts are
  preserved.
- Manage Tokens, live asset filters and Reset, wider catalog browsing, stable
  search rows, and separate token tracking and verification states.
- Bounded background artwork resolution and downloads, downsampling and disk
  caching. Original asset bytes remain available for export.
- Updated welcome artwork, feature rotation and layout, plus Receive QR
  presentation that preserves the original export encoding.
- Independent same-block checks for Monad account classification and recovery
  for interrupted unsigned TRON sends, preserving signed and broadcast records.
- Scanner review, history synchronization, wallet restoration, wallet switching,
  unit-price guidance, tiny-amount formatting and right-to-left presentation
  improvements from the earlier 5.0.3 preview.
- Retains transaction-review and WalletConnect validation repairs merged since
  5.0.2. Existing wallet and encrypted backup formats remain compatible.

New interface strings are included in all 57 supported app languages. Cronos
remains disabled and is not advertised as an enabled network.

## Source identity and verification

Use the build-specific tag, not the earlier `v5.0.3` preview tag. Previously
published tags and [build 105 evidence](5.0.3-build105.md) retain their original
source identities. Verification of older commits is not automatically evidence
for this release.

```sh
git clone https://github.com/OathWallet/oath-wallet.git
cd oath-wallet
git checkout --detach v5.0.3-build110
git rev-parse HEAD
python3 Distribution/verify_release.py --root . \
  --tag v5.0.3-build110 --version 5.0.3 --build 110 \
  --output /tmp/oath-5.0.3-build110-source.json
```

Compare the full commit with the release's `source.json` attachment. The verifier
rejects a mismatched tag, modified tracked source, or inconsistent version/build
settings. `project.yml` and both Xcode configurations specify **5.0.3 / 110**.

With Xcode 27, Python 3 and Gitleaks installed, reproduce the release gates:

```sh
python3 -m unittest discover -s Distribution/tests -v
python3 Tools/ValidatePublicRelease.py --scan
python3 Tools/CheckDiagnosticsCoverage.py
python3 Tools/CheckLocalizationCatalog.py
swift test --package-path Packages/OathDiagnostics --build-system native --jobs 4
OATH_TRACE_OUTBOX_TEST=1 swift test --package-path Packages/OathDiagnostics \
  --build-system native --jobs 4 --filter DiagnosticTraceTests
OATH_PROPAGATION_CAPTURE=1 swift test --package-path Packages/OathDiagnostics \
  --build-system native --jobs 4 --filter ReportedDiagnosticFailureTests
sh Tools/PreparePublicBuild.sh
xcodebuild -project OathAtmosphere.xcodeproj -scheme OathAtmosphere \
  -configuration Release -destination 'generic/platform=iOS' \
  -derivedDataPath /tmp/oath-503-110-build \
  -archivePath /tmp/oath-503-110.xcarchive \
  CODE_SIGNING_ALLOWED=NO archive > /tmp/oath-503-110-build.log 2>&1
python3 Tools/CheckArchiveSymbols.py /tmp/oath-503-110.xcarchive
```

Check the build command's exit status before running the archive checker. No
provider credentials are needed to compile; the preparation script creates an
empty ignored configuration. No simulator or physical device is launched by
these commands.

## GitHub verification and later upload

In **Actions → Release app and website → Run workflow**, choose `main` and enter:

| Input | Value |
| --- | --- |
| Version | `5.0.3` |
| Build | `110` |
| Source tag | `v5.0.3-build110` |
| Verify only | **Enabled** for verification without deployment |

The verification run checks the exact tag, validates the source, runs host tests
and creates an unsigned generic iOS archive. Its `verified-source` artifact
contains `source.json` with the full source commit. The release attachments retain
the source identity and validation record beyond Actions artifact expiration.

When the maintainer is ready to upload, use the same inputs with **Verify only
disabled**. That existing workflow also deploys the website, signs and uploads
the selected app build, and waits for Apple processing. **It does not submit for
review.** Choose the processed build and submit manually in App Store Connect.
Apple agreements and encryption compliance must be resolved separately when
required. Never rerun upload after Apple has accepted the same version/build.

After an upload, inspect the `app-store-release-receipt` artifact. Its
`receipt.json` must identify this tag and full source commit, version **5.0.3**,
build **110**, `uploaded_and_processed`, and Apple's build identifier. Verify the
GitHub attestation using:

```sh
gh attestation verify receipt.json --repo OathWallet/oath-wallet
```

No Apple receipt exists merely because a source release or verification run
succeeded. A future receipt links the workflow's archive to its uploaded build;
Apple may transform the distributed binary. This is build provenance, not proof
of byte-for-byte equivalence with the App Store download.

## Validation record and limitations

See the release's `verification-5.0.3-build110.json` and accompanying sanitized
validation transcript for measured results and exact commands. Host assertions,
defined test cases, build checks and skipped opt-in cases are reported separately.

Release-preparation checks on 9 November 2026:

- Release identity, signing preflight and upload-only lane fixtures: **12 tests
  passed**, using synthetic data with no signing or Apple requests.
- On-device diagnostics: **125 unique tests passed**, **1 live check skipped**,
  **0 failures**. The default suite ran 126 cases with 3 skips; the two isolated
  recorder cases were subsequently run successfully in separate processes.
- Diagnostics coverage: **757 observed catch sites**, guard passed.
- Localization: **0 findings across 3 catalogs**.
- Publishable-source validation and its Gitleaks scan passed.

- Unsigned generic iOS **Release archive passed** using Xcode **27.2 (27B52)**
  and Swift **6.4.2**. Its built Info.plist identifies **5.0.3 / 110**.
- Both Wallet Core device frameworks and their archived debug symbols match the
  pinned provenance identifiers.
- The archived iOS diagnostics module passed its API and binary checks. The
  archive's module layout was mapped into the checker's expected build-products
  layout with temporary symlinks; the compiled module and binary were unchanged.
- The whole-directory Gitleaks check also passed with no findings.

The feature integration was tested before the build-number update at source
`04f74a7aad1a8c8f4b9cd9a140fb47962a9fd81e` and merged through
[PR #151](https://github.com/OathWallet/oath-wallet/pull/151). Its implementation
is retained in build 110; the build-110 release gates are recorded separately.
Those feature checks covered all 42 enabled networks and included 337 passing
send-preparation tests with 32 opt-in runtime/live cases skipped. Additional host
harnesses covered recipient validation, exact amounts, receive selection, asset
filtering, artwork, cancellation and lifecycle behavior.

No new simulator, physical-device or live-transaction check is claimed for this
release. These are maintainer-directed checks, not independent certification or
a completed security audit. The ongoing
[security review](https://github.com/OathWallet/oath-wallet-security-review)
retains its own tested commits and outstanding scope.
