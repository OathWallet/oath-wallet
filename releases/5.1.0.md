# Oath Wallet 5.1.0 (110)

Stable source release: [`v5.1.0-build110`](https://github.com/OathWallet/oath-wallet/releases/tag/v5.1.0-build110).

## Changes

This release packages the features in [5.0.3 (109)](5.0.3.md) under version 5.1.0 and build 110: wallet sidebar, stable portfolio rows, recent activity preparation, committed wallet names and colors, localized send guidance, Bitcoin fee relationships, resilient balance/price reads, and token artwork recovery. Application source and dependencies are unchanged from that tested release; version settings and release documentation are updated.

## Build and delivery evidence

The GitHub release workflow checks out the immutable tag, validates its version and build, runs checks, compiles an unsigned archive, then signs and uploads the same source commit. It does not submit for review. Upload and Apple processing are not evidence of public App Store availability.

The release attachments will include `source.json`, the Apple `receipt.json` and its GitHub attestation once delivery succeeds. Do not infer successful delivery from this source record alone. The receipt must report `uploaded_and_processed`, version `5.1.0`, build `110`, and the exact Apple build identifier.

```sh
git clone https://github.com/OathWallet/oath-wallet.git
cd oath-wallet
git checkout --detach v5.1.0-build110
python3 Distribution/verify_release.py --root . --tag v5.1.0-build110 \
  --version 5.1.0 --build 110 --output /tmp/oath-5.1.0-source.json
gh attestation verify receipt.json --repo OathWallet/oath-wallet
```

Compare `source_commit` with `git rev-parse HEAD` and the release's `source.json`. The receipt records the workflow run, source commit, toolchain and pre-upload IPA SHA-256. GitHub's attestation authenticates the receipt produced by that workflow. Provider configuration and signing credentials are supplied by protected Actions secrets, not included in public source.

This establishes source-to-upload provenance, not byte-for-byte equivalence with Apple's processed App Store binary or a guarantee of zero vulnerabilities. Earlier test evidence retains its original tested commit. No simulator or physical-device validation is claimed for this version change.

## Reproduce and run

Use the [build and test commands](5.0.3.md#reproduce-validation), with a fresh output directory. The publication checks and unsigned build are repeated for this version; feature regressions are unchanged.

In **Actions → Release app and website → Run workflow**, choose `main`, version `5.1.0`, build `110`, source tag `v5.1.0-build110`. Keep **Verify only** enabled for compilation only. Turning it off runs the existing website deployment and uploads the app to Apple without submitting for review. Never repeat an upload after Apple has accepted this version/build.
